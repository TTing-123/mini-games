# SURGE 设计与市场调研

## 每步玩家在判断什么

**把棋子落在哪个空格，以及把该格所在的整行或整列推向哪边。**

这是一个新的决策类型，不是给 Pulse 的物理连锁或 Casebook 的信息筛选换皮。

## 市场检查

使用：

```powershell
node tools/market-check.mjs "push board game" "abstract strategy push pieces" "row column push board game"
```

结果：

- Steam 搜索中的 “push board game” 命中 0 个 PC 商业作品。
- itch.io 每页固定返回 54 条，不能当总量；头部可见项包括 Push Fight、push, push, push!、Push Box Puzzle。
- GitHub 可查到 Push Fight 求解器、PushySquares、Pushback，以及直接相关的 Boop（落子时把相邻棋子推开）。

进一步查看头部机制：

- **Push Fight**：棋子在狭长棋盘上被推来推去，核心是把对方棋子推下台。
- **Boop**：每次落子会把相邻棋子推开一格，核心是做三连。
- **Abalone**：通过推挤对方弹珠，把对方弹出棋盘。

## 差异

SURGE 不推相邻棋子，也不以“把对方全部推光”为胜利条件。

它每次推的是**完整一行或一整列**，并且每个回合都会改变棋盘；玩家需要在这个持续移动的棋盘上建立跨上下或跨左右的连通线。胜负来自连接，而不是吃掉对方。

这不是“换画面”或“做简单版”，而是同一个推挤直觉下的不同决策结构：Push Fight / Boop / Abalone 判断局部推挤方向，SURGE 判断全局行列表面的移动方向和连线后果。

## 原型的自动化检查

- 开局合法拖拽：168 种。
- 逻辑测试：11 项通过。
- AI 自动对局：2 局 AI 均获胜，分别在 22 手、20 手结束。
- 浏览器操作：自动拖拽、AI 回手、胜负弹层、移动端布局均通过，无控制台报错。
- 首轮真人反馈：不懂规则。
- 调整：加入首次打开的三步视觉引导、常驻玩法三步条、首回合强制演示，以及右上角「怎么看」入口。
- 后续试玩：重点确认玩家是否能自己完成第二次推线。
