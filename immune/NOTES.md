# IMMUNE 设计与市场调研

## 机制（第 3 步：机制锁定）

一句话规则：**病毒每回合向外扩散一格，你每回合最多投一针；免疫区同样逐格扩散，把所有人都盖住就算赢。**

- 病毒先动，免疫后动：被病毒占过的格子不会变回来。
- 病毒碰到人 → 立刻失败；所有人被免疫覆盖 → 立刻胜利。
- 疫苗只能投在地图上的**投放点**，每回合最多投一针；投放点被病毒吞掉就不能再用了。

每步判断：这一针投在哪个投放点，免疫才能抢在病毒之前盖到人（考虑墙、距离差、以及投放点自己会不会先被吞掉）。

## 判断类型为什么是新的

已保留的四款：瞄准物理（PULSE）、证词推理（CASEBOOK）、格子约束（NONO）、整盘滑行（TILT）。
本作判断的是**两个扩散front的时序竞争与覆盖**：不是把一个东西送到某处，而是判断「谁先到」。
已否决的「齿轮配比」正是反面案例：一步只产生一个数字，没有揭晓；本作每一步都会看到两波颜色推进、相撞、被挡住。

## 市场检查

```powershell
node tools/market-check.mjs "cellular automaton puzzle game" "conway game of life puzzle" "domino chain reaction puzzle" "infection spreading puzzle game"
```

结果（Steam / itch 这次通）：

| 关键词 | Steam | GitHub | itch 首屏 |
| --- | --- | --- | --- |
| infection spreading puzzle game | 0 | **0** | 命中的全是感染题材动作/射击（Downfall / AMEBA / Eradicate），不是扩散解谜 |

## 差异说明

不是「我做得更简单」：现有 itch/Steam 上的感染题材都是动作射击（你操作角色打病毒），本作把「病毒 vs 免疫」抽象成**两波同时扩散的front**，玩家不控制角色，只决定投放点与时机——判断对象完全不同。

## 难度来源

- 墙导致绕路：看的距离不是直线距离
- 多人：必须分兵，每回合只能投一针 → 顺序
- 投放点会被吞：晚一步就没得用
- 多病毒夹击：两侧同时压过来

## 原型检查

- 关卡：12 关手写，全部由 tools/level-audit.mjs 复核：可解、无墙体重复、最少针数从 1 → 2 → 3 递进（第 9 关要三针）。
- 逻辑测试：11 项通过（病毒先手、同格病毒赢、免疫不能穿红、人必须被覆盖、每回合限一针、投放点被吞、感染即败、提示可行、教学关 1 针、最后关 2 针）。
- 端到端：桌面鼠标 + 手机触屏 17 项通过，含「连点推进不丢手」「投第二针被拒」「胜利与失败两条结算路径」，无控制台报错。
- 真人试玩：等待反馈（决定继续 / 调整 / 放弃）。

## 已知取舍

- 投放是「点投放点」一步，没有拖拽；每回合限一针的节奏靠按钮推进。
- 目前没有「主动隔离墙」之类的新装置，难度只靠地图、病毒数、人数与投放点位置；如果要更多层，再考虑加「免疫可以被消耗」这类规则。
