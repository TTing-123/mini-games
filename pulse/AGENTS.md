# 游戏项目开发规则

## 项目定位

pulse 是一个浏览器即时游玩的 2D 回合制物理连锁弹球游戏。

核心幻想：玩家通过一次瞄准，让物理系统自行产生反弹、分裂和引力连锁。玩家通过试验而不是说明文字理解玩法。

## 技术栈

- 静态 HTML / CSS / JavaScript ES Modules
- Canvas 2D 负责游戏渲染
- DOM 负责 HUD、教程、关卡选择和结算
- 不使用 Godot、Unity、Unreal 或运行时前端框架
- 不依赖构建工具；使用静态服务器即可运行

## 默认开发流程

1. 新玩法默认先走 GDS Quick Flow。
2. 核心逻辑优先放入可独立测试的纯函数或 GameCore。
3. DOM 层只负责渲染、输入和界面状态。
4. 原型必须实际运行、可操作，并完成至少一次人工 Playtest。
5. 记录 Playtest 反馈和“继续 / 调整 / 放弃”的判断。

## 项目约束

- 基础玩法不依赖构建工具。
- 不设实时倒计时，不考核反应速度。
- 玩家主动作保持为瞄准和发射。
- 视觉方向保持深海实验室：深青色生物发光背景、玻璃舱 HUD、机关旁的发光标签。
- 不添加独立全屏教程；每种新机关必须在对应第 1～4 关中通过场内标注和首次碰撞自然教学。
- 连击奖励必须绑定到同一发射击流程。
- 黄块分裂必须限制为一次，禁止无限指数增长。
- 绿色充能机关必须限制为单次触发。
- 无尽模式实体数量必须设有硬上限。
- 音乐不是必需品，优先使用碰撞、分裂、爆炸和引力反馈音效。

## 代码结构

- src/game-core.js：纯游戏状态和物理逻辑，不访问 DOM。
- src/game.js：Canvas 渲染、输入和界面交互。
- src/style.css：视觉系统、响应式布局、教程和 HUD 样式。
- tests/game-core.test.mjs：Node 内置测试运行器。
- index.html：DOM 结构和界面文案。

## AI 工具协作

- Claude Code 和 Codex 共享 _bmad/、_bmad-output/ 和 Web 源码。
- 同一工作区同一时间只允许一个工具主导文件编辑。
- 并行开发使用不同 Git 分支或 worktree。
- 关键决策写入仓库工件，不依赖聊天记录。
