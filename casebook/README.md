# Casebook / 案卷

手写案件推理。你是一个办案的人，手上只有有限的提问次数。

在线试玩：<https://tting-123.github.io/mini-games/casebook/>

## 怎么玩

1. **挑人问**。左边是嫌疑人，选一个，从他那几个话题里挑一个问。每问一句都扣一次机会，问过的话题不能重复问。
2. **交叉比对**。证词之间会互相打架——某个人说的时间，和另一个人看到的对不上。矛盾就是突破口。
3. **指认**。觉得有把握了就开指认面板。**光说"是他"不算破案**，你还得指出哪句话是决定性的。指对人但举错证据，一样算失败。

提问次数是紧的：每个案子 9～12 条可选证词，但只给你 6 次机会。所以"先问谁、先问什么"本身就是要判断的事。

右上角有两个常驻按钮：**案卷**（换案子，破过的打勾）和**重来**（清掉这次问到的所有证词，重新开始当前案子）。破案记录写在浏览器本地，关掉再打开还在。

| 第二案 · 末班车 | 公交司机死在终点站驾驶座上。三个乘客里，有一个在"什么时候醒的"这件事上撒了谎 |
| 第三案 · 同住一店 | 旅店住客中毒身亡。有人给自己安排了下棋的不在场证明，可惜对面那位记的时间对不上 |

案子是手写的，不是随机生成的——推理游戏的味道在文字里，机器拼出来的证词读起来是干的。

## 测试

```powershell
node --test casebook/tests/*.test.mjs
```

除了流程（提问消耗、不能重复问、指认判定），有两组是**给案件数据做体检**的：

- 每条决定性证词必须真实存在于某个嫌疑人的话题里，不能指向不存在的话
- **关键证词条数不能超过提问预算**，否则玩家根本问不全，案子就成了死局
- 提问预算必须小于总证词数，否则没有取舍

以后加案子，这两条会自动把关。

## 架构

- `src/cases.js`：案件数据（纯数据，手写）
- `src/case-core.js`：审问与指认的状态机，不碰 DOM，可在 Node 里跑
- `src/game.js`：界面渲染与交互
- `src/style.css`：卷宗风格排版

## 案子结构（三种不同的谎言）

写案子时我刻意让每个案子的"破绽类型"不一样，避免变成同一种思考方式：

- **第一案**：在**时间**上撒谎——自称早走了，但车还停在院子里
- **第二案**：在**状态**上撒谎——自称醒来时车已停，可别人喊他时他正睡着
- **第三案**：在**不在场证明**上撒谎——拉了个下棋的搭子，但两人对同一盘棋的说法对不上

## 之后可以加

- 更多案子（每个案子独立，互不影响）
- 案件里加"物证"，让线索不只来自嘴
- 指认时要求指出**两处**矛盾，进一步收紧
