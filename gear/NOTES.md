# GEAR 设计与市场调研

## 候选机制（各写「玩家每一步在判断什么」）

| 候选 | 每一步玩家在判断什么 | 判断类型 | 结论 |
| --- | --- | --- | --- |
| A 齿轮传动（本作） | 这一级装哪一对齿轮，累计传动比能不能让输出指针停在目标刻度 | 比例累乘 + 资源分配 | 采用 |
| B 多级杠杆平衡 | 砝码放哪个刻度，本级和上层同时平衡 | 力矩平衡 + 连锁约束 | 备选（反馈是二值，操作感弱） |
| C 波源相位干涉 | 波源放哪、相位调多少，目标点正好抵消 | 相位叠加 | 备选（抽象，规则难一句话讲清） |

已排除：与现有四款撞类型的方案——瞄准物理（PULSE）、证词推理（CASEBOOK）、格子约束（NONO）、整盘滑行（TILT）。

## 市场检查

网络限制：本机访问 Steam 商店 API 与 itch.io 均失败（fetch failed），GitHub 直连可用，因此以 GitHub + 人工判断为准：

```powershell
node tools/market-check.mjs "gear ratio puzzle" "gear train puzzle game" "mechanical linkage puzzle"
```

结果：

- GitHub：`gear ratio puzzle` 0 命中，`gear train puzzle game` 0 命中，`mechanical linkage puzzle` 1 命中（mechanism-master：四杆机构追踪曲线，机械工程教授做的）。
- 结论：**「齿轮箱配比」作为核心判断的迷你解谜没有头部作品**；工程解谜的头部（Zachtronics 的 Opus Magnum / Infinifactory / SpaceChem）都是「自由构造机器 + 多步编程」，单关十几分钟起步。

## 差异（第 3 问：不是「我做得更简单」）

- 头部是**自由构造 + 连续调试**：玩家搭一条产线，一步几十秒。
- 本作是**有限槽位 + 精确目标**：齿轮池每个只能用一次，判断集中在「比例累乘对不对」，一关 10～30 秒。
- 差异不在规模，而在**判断对象**：头部判断「流程编排」，本作判断「传动比与零件分配」。

## 机制

一句话规则：**每一级把「从动齿数 ÷ 主动齿数」乘进总传动比；齿轮池里每个齿轮只能用一次。让输出指针停在目标刻度。**

- 输入轴固定转一圈（360°）。
- 输出角 = 360° × ∏(从动 ÷ 主动)，再对 360° 取余；每级啮合反向一次。
- 判定：输出角落在目标刻度的 ±7.5° 内。

每步判断：这一级装哪一对齿轮，累计比还差多少；哪个齿轮留给后面用。

## 难度来源

- 比例累乘（1/2 × 3/4 …）
- 零件唯一：装错要拆，取舍
- 级数越多，组合爆炸（4 个零件 = 24 种排法，6 个 = 720）
- 目标精确到 15°，凑近似值不算过

## 原型检查

- 关卡：10 关手写（1～3 级），全部由 tools/level-audit.mjs 复核：目标可达、无重复配置、解数已压到该齿轮池的最低档（1 级 1/2～1/6，2 级 4/24～4/120，3 级 36/720）。
- 逻辑测试：10 项通过（传动比、反向、零件唯一、空槽、目标判定、角度取余、提示可行性、每关可解）。
- 端到端：桌面鼠标 + 手机触屏 15 项通过，无控制台报错；连点装配、拆回、跳关、结算都覆盖。
- 真人试玩：等待反馈（这一步会决定「继续 / 调整 / 放弃」）。

## 已知取舍

- 方向目前由级数唯一决定（奇数级反向），玩家没有换向选择；如果试玩觉得少一个维度，再引入「惰轮位」（装惰轮只换向、不改比例，但要占掉一个齿轮）。
- 零件盘用「点选 → 点槽」两步，没有做拖拽；如果觉得手感不够快，下一步改成拖拽 + 点选都支持。
