# TILT 设计与市场调研

## 每步玩家在判断什么

**这一倒，哪些方块会停在哪一格、谁会被谁挡住、谁正好落进凹槽。**

判断的是"整块板子的终局形状"，不是某个格子。方块越多，一次倾倒的连锁结果越难预判，这就是这游戏的自发复杂性来源；颜色章节再加一层"谁只能进哪个槽"。

## 市场检查

网络上 Steam / itch 接口在当前网络环境下取不到（fetch failed），GitHub 直连可用，所以这次调研是 GitHub + 人工判断：

```powershell
node tools/market-check.mjs "ice sliding puzzle" "tilt board slide blocks puzzle" "gravity slide puzzle all blocks"
```

- GitHub：`ice sliding puzzle` 77 个仓库，多为个人实现、生成器、求解器（Ice-Sliding-Puzzle 生成器、Aycblok 程序化生成、若干 jam 项目）。
- `tilt board slide blocks puzzle` / `gravity slide puzzle all blocks`：0 命中。
- 头部形态：冰面滑动是**单方块**迷宫这一经典解谜玩法的常见子类，散落在各种 app 与课程作业里，没有占据心智的头部作品。

## 差异

- 经典冰面谜题是**一个**方块；这里改成**所有方块一起滑**，判断对象从"一条路线"变成"整块板子的堆叠顺序"。
- 31 关起加"同色才吸收"，把"停在哪"升级成"谁必须停在哪、按什么顺序"。
- 逐关验证可解性，最短步数由 BFS 给出；提示直接闪最短解的第一步。
- 凹槽停在上面才吸收、滑过不算，这条规则让"停在哪儿"成为唯一的判断对象。

## 关卡怎么来的

手工画地形（墙、凹槽、颜色位置），工具负责穷举与查重：

- `tools/level-forge.mjs`：单方块，穷举 (起点, 凹槽)，按解法去重后给出候选。
- `tools/level-forge2.mjs`：多方块，手放凹槽，穷举方块起点组合（可指定颜色），按解法去重。
- `tools/level-lab.mjs`：打印"几步能停到哪一格"的热力图。
- `tools/level-report.mjs` / `tools/level-audit.mjs`：逐关验证可解性、最短步数、解法重复、墙体相似、镜像对称。

设计原则：**一关一个思路**。52 关的最短解两两不同（已写进测试），同尺寸关卡内部墙体的 Jaccard 相似度全部低于 0.7，也不使用镜像对称的布局。

## 规模

- 52 关（0–30 纯几何，31–51 颜色章节）。
- 最短步数 1–13 步，棋盘 5×5 到 12×12。
- 逻辑测试 16 项：倾倒、叠放顺序、吸收判定、颜色匹配、状态不可变、提示有效性、关卡可解性与查重。
- 浏览器实测：桌面 + 手机触屏均通过，无控制台报错。

## 待办

- 关卡可以继续加；加之前先跑 `level-audit.mjs`，确保新关卡的解法与墙体都和已有不撞。
- 如果玩家觉得颜色章节太晚，可以把"同色"提前到 20 关附近。
